# Native YAML decoder (YAML plan Task 2), measured on `2c95139` + Task 2

`rbe-x86-64.txt` is the output of `//yaml/native:bench` (`yaml/native/bench.cc`, a manual
`cc_test` so that it executes on a BuildBuddy RBE Linux x86-64 worker), run once:
`bazel test //yaml/native:bench --test_output=all`, invocation
<https://app.buildbuddy.io/invocation/6dab4ca1-100a-4e09-8733-a625561cdf77>. Fixtures are the
probe's (`yaml/native/testdata`, regenerated by
`benchmarks/results/yaml-probe-b242abd/sources/fixtures.py`). Every variant parses a fresh copy of
the input; each figure is the best of 7 rounds of a tight loop. **Timings are advisory**: one
shared worker, one run, no confidence intervals; compare rows within this file only.

Rows:

- `ryml-ints(scan)`: rapidyaml's integer event handler (`src_extra`, benchmark only), the probe's
  scan row and the plan's reference;
- `ryml-tree`: rapidyaml's stock tree parser;
- `td-session(decode+reset)`: `td_yaml_session_decode` + `td_yaml_session_reset` (borrow);
- `td-session(retain+release)`: decode, `td_yaml_session_retain`, `td_yaml_release`.

`records-stream` is multi-document input: `session_decode` rejects it (status 7); the stream API
arrives with Task 3.

## Acceptance hypothesis (Task 2 Step 4)

| Hypothesis | Measured (same run, records-block) | Result |
|---|---|---|
| session decode ≥ 0.8 × `ryml-ints(scan)` | 164.4 / 297.0 MB/s = **0.553** | **missed** |
| (rapidyaml's own tree builder, for scale) | 243.2 / 297.0 MB/s = 0.819 | — |

Diagnosis (local arm64 profile of the same code, `sample` over a decode loop, and by switching
each feature off in a scratch copy of the handler; advisory): the session decode does strictly more
than the integer handler, which writes three integers per event into a presized array. Over the
records-block fixture (31,001 nodes) the additions cost, in decode time:

| Work | Share |
| --- | --- |
| Strict UTF-8 + c-printable validation with the LF bitmap (SWAR, 8 bytes per step) | ~5% |
| `lexical` spans (single-line detection for plain scalars) | ~10% |
| Duplicate-key tables (after resolution) | ~5% |
| Three side tables (`lexical`, `key_hashes`, `yaml_meta`) | ~5% |
| Scalar resolution and key stringification | ~5% |
| Node writes (`tape_writer`) and the handler's own dispatch | the rest of the gap |

The probe's generic-builder row (0.73 on arm64) did none of validation, side tables, duplicate
keys or spans. Closing the gap needs either fewer guarantees (no spans, no duplicate check) or
fusing validation and span detection into rapidyaml's own scan, which would need a rapidyaml patch
(excluded by the plan). Recorded as a ledger ruling. Text-heavy input, where scalars are long and
nodes few, decodes at 553 MB/s (0.72 of the scan row).
