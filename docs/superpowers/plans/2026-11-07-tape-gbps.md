# Lean Tape and Tapeless Paths for GB/s JSON and YAML Decode: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Record rulings in `docs/superpowers/plans/2026-11-07-tape-gbps-ledger.md` (create it at Task 1). Every number below is a measured ratio or a labelled hypothesis; acceptance is by the gates, never by a single absolute.

**Goal:** Take JSON decode from 0.26–0.28 × simdjson's ceiling to GB/s-class on unclemax for every use case that retains nothing or retains a document, keep compiled reads, allocation and strictness at or better than today, and put YAML on the same representation.

**Architecture:** One format-neutral **compact tape** (`//tape/native/ctape.h`, Java `TapeReader`) replaces the Myna value tape plus its three side tables as the hot-path representation: one 64-bit word per value, a second word only for numbers, containers and owned (escaped) text; lexical spans, the ASCII flag and the key position live in the words; the per-object directory that compiled reads already use is built from the key hashes the decoder computes anyway and **detects duplicate keys while it sorts**, so the separate duplicate table disappears. The producer stays simdjson On-Demand (a lean walk; the probes show no cheaper public path: a virtual sink costs as much as the tape, a DOM transcode plus duplicates and directories ties it, and a first-cut hand-written stage 2 ties it). Consumers that retain nothing (validate-only, typed plans) run the same walk with no writer. Java sinks (`JsonSink` export, the GraalJS `JSON.parse` path, NDJSON streams) read the compact tape in one pass: for a Java consumer the tape *is* the cheapest event stream, since any upcall-per-event path costs more than a word store. The Myna value ABI stays the interchange format, produced on demand from the compact tape (snapshots, release consumers, Myna-only readers) and proposed upstream as Myna's next layout. YAML's rapidyaml handler writes the same tape through the same writer (with its rewrite operations), aliases become `REF` words, and its two JSON-shaped side tables go away.

**Tech Stack:** C++17, simdjson 5.1.1 (On-Demand; `dom_parser_implementation::stage1` only in the gated spike), simdutf, Myna 0.11.0 (`myna_value_hash`, ABI v4 for the on-demand interchange tape, `myna_tape_text_v1` unused), GraalVM 25 SVM `@CFunction` / JVM FFM from `json.seam` (abi 7) and `yaml.seam` (abi 2), Truffle DSL, Bazel with Linux amd64 RBE, unclemax for paired measurements.

**Spec:** `JSON_PLAN.md`, `docs/superpowers/plans/2026-11-06-json-completion.md` and `2026-11-06-json-performance.md` with their ledgers (every ruling stands unless renegotiated in §2.4), `2026-11-06-yaml.md` and its ledger, `docs/JSON.md`, `benchmarks/comparison/JSON.md`, Myna `docs/values.md` (ABI v3/v4, REF, metadata, rebindable readers, prepared keys).

**Baseline:** `7f55043` on `feat/perf-v4` (0.8.0 + Myna ABI v4 adoption, CSV fixes, protobuf ABI 9). Measurements: `benchmarks/results/json-v4-86a691a/` (unclemax pairs and the scoreboard) and `benchmarks/results/tape-gbps-probe-7f55043/` (this plan's probes, RBE).

**Parallel plan:** `docs/superpowers/plans/2026-11-07-protobuf-performance.md` (another worker). §8 lists the abstractions the two plans share; a task here that changes one of them says so in its ledger line.

## Global Constraints

Everything in the completion and performance plans' Global Constraints, plus:

- **Strict JSON is unchanged:** duplicate keys rejected after escape decoding at every object size (now inside the directory sort), member order preserved, exact number tokens (every number word carries its token span; numbers simdjson cannot type stay `DECIMAL` spans), `-0` is F64 −0.0, trailing input rejected, deferred unescaping only for bodies with no `\` and no byte below 0x20, UTF-8 validated by stage 1 before any body is referenced.
- **No half-published results:** a document is published only after its whole walk, its directories and its duplicate checks succeed; a failed decode leaves the session empty and reusable. Validate-only and typed walks run the same checks.
- **Owners are thread-confined; close invalidates every view** (assumption + `check()`), unchanged. Borrowed documents end before the next session call.
- **Compiled reads:** ≤ 0.05 B/read on SVM (`CompiledReads`), interop root ≤ 2,000 graph nodes, 1 loop, 0 invokes, 0 graph allocations (`json_smoke.py`), no `BigInteger`/`BigDecimal` in partially evaluated code (DECIMAL stays a span; conversion stays behind boundaries), no instance boundaries on fresh views. These gates are never loosened by this plan; a task that would need to loosen one stops and records why.
- **The `JsonSink` single-pass export contract**, `TruffleSink` and the per-document text arena, snapshots, typed plans and NDJSON streams keep their public Java API. `TapeSink` events are unchanged.
- **YAML stays on the shared layer** with aliases, merge keys, last-wins duplicates, tags, non-finite floats and multi-document streams; `//yaml/conformance:yaml_test_suite` stays at 402/402 and the fast-path parity test stays byte-identical.
- **Public simdjson APIs only** on the production path (unchanged). The stage-2 spike (Task 9) reads `dom_parser_implementation::structural_indexes`, a public member of an `internal` type; it is a spike until it clears its gate and the user accepts the dependency (§11).
- **Memory bounds:** a retained document is its padded input, its words (≤ input bytes + 2 words), its owned pool (≤ input bytes) and its directories (8 B per member); a session keeps at most the largest padded input it saw (bounded by `maxInputBytes`) plus arena blocks (≤ 4). The text arena bound (`2 × length + 16`) is unchanged.
- **Performance claims** only from the retained harnesses (`json_smoke.py`, `json_measure.py`, `CompiledReads`, `//yaml/native:bench`, the probe in `benchmarks/results/tape-gbps-probe-7f55043/gbps_probe.cc` re-run as a temporary target) with results under `benchmarks/results/tape-*`, paired on one host. RBE rows are compared within one run.

## Review Focus

1. **A directory-fused duplicate check must reject every duplicate the key table rejected.** Equal hashes are byte-compared after sorting; objects of one member need no directory and cannot hold a duplicate; objects whose directory is skipped (none: threshold is 2) must not exist. Pinned by Task 2's `duplicates_detected_in_sorted_directory` (adjacent and non-adjacent duplicates, hash collisions with different bytes, escaped-vs-raw spellings, 40-key objects, the 17th key duplicating the 1st).
2. **Second words must never be read as nodes.** Every reader step computes the next index from word 0's kind and `WIDE` bit; the export walk, `next()`, `first()`, element indexing, snapshots and the Myna converter are pinned by Task 1's `walk_matches_reference` over the 200-document corpus and by `validate()` (which rejects a word whose kind is `0xF`).
3. **Spans are exact tokens.** `numberText()`/`rawText()`/`decimalValue` read `[offset, offset + length)` of the retained input (or the raw span word of an owned string); a stream document's offsets index the session's copy, not the carry-over buffer. Pinned by `JsonExportTest` decimal parity and `stream_boundary_exactness` reading `rawText()`.
4. **A compiled hit must prove the hinted key belongs to this object.** The directory entry's key offset is relative to the object word and the key word carries the `KEY` flag; the hit path compares the key's bytes in the input against the prepared key words (masked by length). Pinned by `JsonInteropTest.hintMissAfterShapeChange` and `directoryRankHintsSurviveMemberOrderAndShapeChanges`, unchanged.
5. **Snapshots re-base every offset.** A `HeapTape` copies the subtree's words, re-bases `next`, directory indexes, REF targets and input offsets (it copies only the subtree's raw input span) and its pool offsets. Pinned by `TapeOwnerTest.snapshotsReadLikeTheirSources` over every node of the corpus, including YAML tapes with REF.
6. **YAML rewrites keep the tape well-formed.** `erase`/`append`/`truncate` on the compact writer renumber `next`, REF targets and directory indexes; a directory is built only after the mapping's merges and removals. Pinned by the conformance suite, `fast_path_test` parity and `merge_test` (anchored-node removal still an error).

## 1. Diagnosis

Numbers in §1.1–1.3 are from `benchmarks/results/tape-gbps-probe-7f55043/` (RBE worker, `icelake`; see its README for rows and caveats). This worker runs the shipped decoder 1.35–1.4× slower than unclemax (`V4`: 466 ns small / 9.3 ms huge here against 340 ns / 7.05 ms in `json-v4-86a691a`); the ratios are the evidence, and §1.4 scales the ceilings to unclemax. Java-side numbers in §1.5 are unclemax medians from `json-v4-86a691a`.

### 1.1 Where the shipped decode goes (228 KB array, round 3; round 2 for rows not in round 3)

| Row | ns | MB/s | Adds |
|---|---:|---:|---|

| T8 + compact 8-byte tape | 305,257 | 749 | the tape proper: +5 % over a virtual sink |

| V3 shipped visitor, ABI v3 (round 2) | 442,924 | 516 | **lexical spans + key meta: +35 % over T24** |
| V4 shipped, ABI v4 directories (round 2 / 3) | 461,575 / 468,299 | 495 / 488 | directories: +4 % |

Reading the table:

- **The tape's side tables are the single largest avoidable cost** (T24 → V3): one `uint64` span and one `uint32` meta per node, pushed through two more `arena_vec`s per value, cost more than the 24-byte nodes themselves. Embedding the span in the node word is free for strings (the decoded body *is* a span) and costs one word for numbers (which need a second word for their value anyway).
- **The duplicate check costs 5 ns per key in every form tried** (round 2: `key_table`, a 64-bit filter, YAML-style per-depth key templates, a one-multiply hash; all within 2 % of each other at ≈ 0.93 GB/s against the same null-writer baseline). The cost is the per-object table life cycle and the hash+compare per key, not the hash function. The directory the readers want anyway sorts `(hash, offset)` per object: a duplicate is an equal hash with equal bytes, found during the insertion sort at no extra structure. That folds the 22 % into the 4 % the directory already costs (hypothesis: ≤ 8 % together; Task 2 measures it).
- **Nothing public is cheaper than On-Demand.** DOM plus a strict duplicate pass and directories (`D0e`, round 2) measures 801 MB/s, the same as `T8x`; DOM also needs a fallback tier for numbers it cannot type (`1E400`, 21-digit integers: `NUMBER_ERROR`), copies every string into `string_buf`, and loses number spans. A first-cut recursive-descent stage 2 over simdjson's structural index (`S2`, round 3b) measures 760 MB/s, the same as `T8`: reaching `D0` would mean reproducing simdjson's SIMD string and number stages, a large engineering item with an uncertain payoff (§9, Task 9, gated spike).
- **A direct sink is not a shortcut** (`W3v` ≈ `T8`): a tape write is cheaper than any call per event, and for Java consumers an upcall per event would cost an order of magnitude more than a word store. The tapeless paths are therefore validate-only and typed plans (no writer at all), not sinks.
- **Not worth it:** the SWAR body scan (`W2s` vs `W2` within 1 %), unchecked writes (`T8x`: +4 % at a 13 % loss on large inputs from the reservation), 16-byte fixed nodes with every span stored (`T16` is 12 % slower than `T8`: the extra word per node costs more than it saves), grammar-only lazy numbers (`W3g`: −8 % of decode but every read would need a number parse; kept as an open option in §11, not in the plan).

// tape/: our reader replaces Myna's ValueTape on the hot path. Abstract, three final subclasses:

Hit path (one straight-line static method over primitives, as today's `directoryKey`):

```java
static long hinted(TapeReader t, long object, int rank, TapeKey key) {
  long w = t.word(object);                                   // kind OBJECT, count
  if (kind(w) != OBJECT || rank >= count(w)) return -1;
  long dir = t.word(object + 1) >>> 32;                      // directory index + 1
  if (dir == 0) return -1;
  long e = t.directoryEntry(dir - 1 + rank);                 // hash | keyOffset << 32
  if ((int) e != key.hash) return -1;
  long k = object + (e >>> 32);
  long kw = t.word(k);                                       // STRING|KEY, length, offset
  if (kw >>> 32 != key.header) return -1;                    // kind, flags(KEY), length in one compare
  long off = kw & 0xffffffffL;
  if (t.inputWord(off) != key.low) return -1;                // key.low is masked by length ≤ 8; else two words
  if (key.length > 8 && t.inputWord(off + 8) != key.high) return -1;
  return k + 1;                                              // the value word
}
```

Six loads for keys of at most 8 bytes, as today. Owned (escaped) keys set the `OWNED` flag and are compared through the pool behind the miss boundary (as keys over 16 bytes are today).

## 3. The compact tape

### 3.1 Words

All words are 64-bit, native-endian, in one contiguous array; index 0 is the root. Bits 60–63 are the **kind**, bits 56–59 **flags**, the rest kind-specific.

| Kind | Code | Words | Bits 0–31 | Bits 32–55 | Flags |
|---|---:|---:|---|---|---|
| NULL | 0 | 1 | 0 | 0 | |
| FALSE / TRUE | 1 / 2 | 1 | 0 | 0 | |
| I64 / U64 / F64 | 3 / 4 / 5 | 2 | token offset | token length (24) | WIDE; word 1 = value bits |
| DECIMAL | 6 | 1 (2 if OWNED) | token offset (input, or pool if OWNED) | token length | OWNED → WIDE, word 1 = raw span |
| STRING | 7 | 1 (2 if OWNED) | decoded offset (input, or pool if OWNED) | decoded length (24) | ASCII, KEY, OWNED → WIDE, word 1 = raw span (`offset << 32 \| length`, the token with quotes) |
| ARRAY / OBJECT | 8 / 9 | 2 | `next`: index of the word after the subtree | count (24, saturating at 0xFFFFFF) | WIDE; word 1 = `directory index + 1` (objects; 0 = none) `<< 32 \| raw offset` of the opening bracket |
| REF | 10 | 1 | target word index | 0 | (YAML aliases; target precedes the reference and is closed) |
| 11–15 | | | reserved; `validate()` rejects them | | |

Flags: `WIDE` (bit 59: a second word follows; set by the writer for every 2-word kind so `next(i)` is `wide ? i + 2 : i + 1` for non-containers), `OWNED` (bit 58: text in the pool), `KEY` (bit 57: a STRING in key position), `ASCII` (bit 56: every decoded byte < 0x80). Limits: a text token ≤ 16 MiB − 1 bytes (`TD_JSON_LIMIT` beyond; `JsonLimits.maxTextBytes` documents it), words < 2³² (input ≤ 4 GiB, unchanged), container counts above 2²⁴ − 1 read as 0xFFFFFF and the Java side counts by walking behind a boundary (`getArraySize` of such an array is a boundary call; pinned).

Traversal: a container's first child is `container + 2`; siblings follow by `next`; the root subtree ends at `word_count`. Objects alternate a `KEY` string word (plus its raw-span word when OWNED) and a value subtree.

### 3.2 Directories and duplicate detection

Each object with ≥ 2 members owns a contiguous run of `count` 8-byte entries `(hash32, key_offset32)` in the directory array, sorted by unsigned hash then offset, where `key_offset` is the key word's index minus the object word's index and `hash` is `myna_value_hash` (FNV-1a 32) over the decoded key bytes. The writer collects `(hash, offset)` on a pending stack as keys are announced (`member_key`), and at `end()` insertion-sorts (≤ 24) or `std::sort`s them into the directory. **While sorting, an entry whose hash equals its predecessor's compares decoded key bytes (through the tape: input span or pool); equal bytes throw `duplicate JSON key`.** Objects of one member get no directory (payload 0); the Java miss path compares that key directly. The directory array lives in the same arena and is published through the descriptor; Myna's `find` semantics (first match in offset order) are preserved by the sort order.

### 3.3 Descriptor

```c
typedef struct td_tape_view {           /* 96 bytes, 8-aligned; json.seam/yaml.seam struct TapeView */
  uint32_t version;                     /* 1 */
  uint32_t flags;                       /* bit 0 NONFINITE (YAML), bit 1 HAS_META */
  const uint64_t* words; uint64_t word_count;
  const uint8_t* pool;   uint64_t pool_bytes;        /* owned text (escaped strings, YAML spellings) */
  const uint8_t* input;  uint64_t input_bytes;       /* retained padded input; spans index it */
  const uint64_t* directory; uint64_t directory_count;
  const uint32_t* meta;  uint64_t meta_count;        /* YAML: one u32 per word (0 for second words) */
} td_tape_view;
```

`JsonResult` (abi 7) keeps `owner`, the accounting fields, `view` (now a `td_tape_view*`) and `text_table`/`text_bytes`; `lexical`, `lexical_count` and `key_hashes` are removed (size 112 → 88). `YamlResult` keeps the same prefix and its own tables (`alias_targets` becomes unnecessary: REF words carry the target).

### 3.4 Writer

`ctape_writer(memory, limits)`: `reserve(words, pool_bytes, directory_entries)` (hint: `input / 3 + 8` words, `input / 8 + 64` pool bytes, `words / 2 + 1` entries; checked pushes, growth by moving within the arena as `arena_vec` does today), `begin(kind, depth) → index`, `end(index, count)` (writes `next`, builds the directory, detects duplicates), `member_key(object, hash)`, `null()`, `boolean()`, `integer(v, span)`, `unsigned_integer(v, span)`, `floating(v, span)`, `nonfinite(v, span)`, `decimal_ref(span)`, `decimal(text, raw_span)`, `string_ref(span, ascii, key)`, `string(decoded, raw_span, ascii, key)` (copies into the pool), `ref(target)`, `truncate(words)`, `erase(first, count)`, `append(words, count, shift)` (renumbering `next`, REF targets and directory indexes; directories are not rebuilt by `append`, their entries are object-relative), `text_of(index)`, `view()`, `validate(view)` (a full structural check used by tests and `td_json_validate_tape`), `to_myna(view, arena) → myna_value_view_v4` (an ABI v4 tape: nodes, inline/region text, directories; REF → Myna REF).

The decoder's hint and block sizing (`decode_hint`) follow the new arrays; `index_allocations` stays 0 in steady state (api_test's 10,000-decode assertion).

### 3.5 Text arena and export

`write_text_arena(view, table, out, cap)` walks the words (one entry per word, 0 for non-text words and second words), uses the `ASCII` flag and reads text from the input or the pool. The bound `2 × input + 16` holds as before (decoded text is never longer than its token). `TapeExportNode` walks words: a scalar is one word (two for numbers), a container pushes `next`; keys are recognised by the `KEY` flag (the stack no longer needs an object bit for key position but keeps it as a check).

## 4. Reads

Rank hints over directories are unchanged in shape (§2.3). `TapeOwner.find` (the miss boundary) binary-searches the directory by hash, confirms bytes through the reader, writes `rank + 1` into the hint; for one-member objects and directory-less YAML mappings it compares keys linearly. Element reads keep the most-recent-index cache and the sequential hint (`index == last + 1 → next(lastNode)`); `next` is one word load now (two for a wide scalar: `i + 2`). `getArraySize` returns `count(w)` unless saturated.

Deopt-target rule (completion plan Task 9) holds: every inline helper reads through `TapeReader.word` and the layout statics are non-trivial (they mask and shift), never foreign one-liners. PE budgets: the interop root measured 1,621–1,678 nodes on v4; the compact hit path has the same number of loads and one fewer compare (header compare folds kind, flags and length), so the hypothesis is ≤ 1,700 nodes; the gate stays ≤ 2,000.

Scalar reads: `I64`/`U64`/`F64` read word 1; `DECIMAL` conversions stay behind boundaries (no `BigDecimal` in PE code); `numberText()` reads the span.

## 5. Myna's role

Myna stays the **interchange format**: `JsonMessage.toMyna()` / `TapeSnapshot.toMyna()` (Java, over `HeapValueTape` as today's snapshot class) and `td_json_result_myna(result, out_view, out_owner)` (C ABI, arena-backed, `td_json_release`-able) produce an ABI v4 tape on demand; the release consumers (`tools/release` JSON consumer, `myna_contract.py`) consume that. Myna's `NativeValueTape`, `kindAt`, `keyMatches`, `Utf8Key` leave the hot path; `TapeKey` keeps Myna's hash and packed-word conventions so a converted tape's directories are bit-identical. `myna_tape_text_v1` and `SimdNativeValueTape` are no longer linked into JSON images (the simdutf transcoding call for long strings moves to our own `@CFunction` over `//bazel:unicode`, which the bridge crate currently provides; the bridge is dropped when nothing else needs `myna-values`).

Upstream requests (file as issues at Task 5; nothing blocks on them):

- **M6 — compact value ABI (v5).** §3 as a proposal: one-word scalars, embedded spans, flags, object-relative directories, REF; a Rust/Java reader in Myna so consumers can read our tapes without the converter.
- **M7 — directory-fused duplicate detection** as a builder option (`enable_v4(threshold, metadata, reject_duplicates)`), for producers that stay on the Myna builder.
- **M8 — `myna_tape_text_v1` over v5** once M6 exists; until then the text arena stays ours (ledger V1 measured ours 1.6× faster beyond small documents).

## 7. YAML

The rapidyaml handler (`yaml/native/decoder.h`) writes through `ctape_writer` with the rewrite operations it uses today (`nodes()`, `text_of`, `truncate`, `erase`, `append`, `nonfinite`, `string_words` → `string_ref`/`string` with precomputed flags). Changes of representation:

- `lexical_` → embedded spans (plain scalars reference the input; quoted/block scalars are OWNED with their raw span); `hashes_`/key meta → `ASCII`/`KEY` flags and directories (built at mapping close, after merges, last-wins removals and `convert_to_pairs`; pairs mappings become arrays and have none); `yaml_meta` stays a `uint32` side table per word (tags, anchors, style; `HAS_META`), published through the descriptor; `alias_targets` → `REF` words (target word index; an alias used as a key stays a KEY string with the meta bit).
- Duplicate policy: REJECT uses the directory sort (keys are canonical STRING text, as today); LAST_WINS and PAIRS keep their explicit paths (they need the earlier entry's position), running before the directory is built; YAML's `key_set` and templates are removed if the directory sort measures no slower on `records-block` (Task 8 Step 4), else kept for the fast path only.
- Non-finite floats set the descriptor flag; the Java `SegmentTape` accepts it (the YAML ledger's open item).
- Gate: `//yaml/native:bench` session decode ≥ 0.80 × `ryml-ints(scan)` on `records-block` (hypothesis; today 0.715 with the engine at 70 % of the profile and our per-node work at 30 %: removing two side tables and halving node stores removes about half of ours) and never below 0.715 in the same run; conformance 402/402; `fast_path_test` byte-identical.

## 8. Shared abstractions with the protobuf plan

Flag for alignment (the other worker reads this section):

1. **`TapeSink` / `JsonSink` events** (`tape/.../TapeSink.java`): unchanged here; a protobuf-to-sink export should emit the same events.
2. **Typed slots** (`TypedLayout`, `TypedRecord`, `TypedAccess`, the `JsonTypedResult` slot arena): untouched by this plan; protobuf's typed messages (`TypedMessage`, `TypedRow` in `protobuf-buffa`) should keep the same slot kinds and presence/null masks if they converge.
3. **Owner liveness** (`TapeOwner.check()`, pins, assumptions, thread confinement, `CheckOpenNode`): unchanged contract; `TapeReader` is new and format-neutral. A protobuf lazy view could be a `TapeReader` over a different word layout only if it adopts §3's traversal rules; otherwise it should reuse `TapeOwner` and define its own reader base.
4. **Descriptor header**: `td_tape_view` (§3.3) is the candidate common "core read API" descriptor; a protobuf result that wants Java `TapeValue` views publishes one.
5. **`TapeKey`** hashing (FNV-1a 32, little-endian packed words) is the one key encoding for every format's directories.

## 10. Risks and non-goals

**Risks**

- *Layout bugs are silent.* A wrong `next` or WIDE bit reads a value word as a node. Mitigation: `validate()` runs in every native test and in `JsonMessage` construction under a debug flag; Review Focus 2; the differential corpus against the `7f55043` decoder through `to_myna`.
- *Hinted hits on escaped keys.* An OWNED key is compared through the pool, which the hit path does not touch; such keys always miss into the boundary. Mitigation: documented; the fixture's keys are clean; a key-cache entry can carry the pool bytes.
- *PE graph growth.* The hit path has one more mask than today. Mitigation: the ≤ 2,000-node gate with the measured 1,621–1,678 baseline; if a fold is needed, the header compare already merges three checks.
- *YAML rewrites on a variable-width tape.* `erase`/`append` must renumber REF targets and directory indexes in addition to `next`. Mitigation: Task 1's rewrite tests use the exact shapes `merge.h` produces; Task 8 keeps `tape_writer` as the parity oracle for one release.
- *Myna consumers.* Anything reading `JsonResult.view` as a Myna descriptor breaks at abi 7 (as intended by the fingerprint). Mitigation: `td_json_result_myna`; release consumers updated in Task 5.
- *The duplicate-fused directory changes the error position* (reported at object close instead of at the duplicate key). Mitigation: the status and message are the same; no API exposes a position today.
- *RBE noise.* All targets are hypotheses; acceptance is by ratios in one run and unclemax pairs.

**Non-goals**

- A DOM-based or two-tier decoder (§1.1: no gain with duplicates and directories; fallback tiers forbidden).
- Lazy per-subtree materialization as a new mode (§2.1: the compact tape carries every container's raw offset; the memory argument for frames shrank from 5.3 × to 1.4–1.8 × input; G1/G2 stay deferred with the trigger "a measured need above 64 MiB documents").
- Lazy number typing (W3g −8 %): rejected for this plan; reads would need number parsing in Java or a leaf call per read.
- simdjson threading or an upgrade; a serializer; JVM comparison cells; minify/pretty-print.
- Changing `TapeSink`, typed slots or the session/stream public API.
- Replacing rapidyaml.

## 11. Open decisions for the user

1. **Myna interchange scope.** Keep `toMyna()`/`td_json_result_myna` as the only Myna surface (proposed), or keep a Myna-tape decode mode (`TD_JSON_MYNA_TAPE`) for consumers that cannot change? Default proposed: converter only; the Myna request M6 brings Myna readers to the compact layout.
2. **Directory threshold.** Objects with ≥ 2 members (proposed) or every object (today's 1)? The singleton case saves a sort and 8 B; the Java miss path compares one key.
3. **The 160 B interop-ingest target** counts 240 B of harness views; the cell can reach ≈ 120 B of our objects. Keep 160 as the gate on *our* bytes (proposed: report both) or redefine the cell?
4. **Stage-2 spike dependency.** If Task 9 clears its gate, accept reading `dom_parser_implementation::structural_indexes` (public member of an `internal` type, pinned at 5.1.1) on the production path? Default proposed: no unless ≥ 1.25 ×.
5. **`fast_float` as a dependency** for Task 9 only (BSD/Apache, header-only), or restrict the spike to simdjson's public number parsing if available.
6. **YAML gate.** Accept ≥ 0.80 × `ryml-ints` as the new gate (hypothesis) with 0.715 as the floor, or keep 0.8 as a hard requirement for Task 8 to merge?
7. **Text-arena fusion (Task 7)** only if TruffleSink misses ≤ 1,550 ns, or unconditionally?

**Decided (user, 2026-11-07): every proposed default.** Q1 converter only (`toMyna()`/`td_json_result_myna`; no Myna-tape decode mode). Q2 directories on objects with ≥ 2 members. Q3 gate on our bytes (≤ 160 B), report the harness's views alongside. Q4 the `internal` structural-index dependency only if Task 9 clears ≥ 1.25 ×, and then by a further user ruling. Q5 `fast_float` allowed for Task 9 only. Q6 YAML ≥ 0.80 × is a hypothesis; 0.715 is the floor that blocks a merge. Q7 text-arena fusion only if Task 6 shows TruffleSink missing ≤ 1,550 ns.

**Ruling (user, 2026-11-07):** PGO stays out of this repository (an application-level concern); no target depends on profiled images.
