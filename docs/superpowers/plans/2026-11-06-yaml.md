# Native YAML Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Record rulings and deviations in `docs/superpowers/plans/2026-11-06-yaml-ledger.md` (create it at Task 1), in the format of the JSON completion ledger.

**Goal:** Parse YAML natively into the same Myna tape, owners, sinks, snapshots and typed plans that JSON uses, on SVM and JVM. Make it the fastest way to get YAML into guest objects (Elide's `YAML.parse`), host objects and typed slots. Strict YAML 1.2.2 is the default, with explicit options for YAML 1.1 behaviour. Measure it against SnakeYAML Engine, SnakeYAML, Jackson YAML and native references, and release it as `dev.elide:truffledata-yaml`.

**Architecture:** rapidyaml 0.16.0 (C++17, MIT) drives a TruffleData `ParseEngine` event handler that writes Myna ABI v3 nodes directly into the JSON performance plan's session arena through its presized tape writer. There is no rapidyaml tree, event array, DOM or Java object tree in between. YAML-only information goes into per-node side tables next to the existing lexical spans and key hashes: scalar and container style, resolved tag, anchor, alias target and original key kind. Aliases are reference nodes resolved on read, so memory stays linear in the input, and expansion is budgeted wherever a consumer materializes them. The format-neutral parts of the JSON stack (owner, value, sink, text cursor, snapshot, export node, typed slots, arena, tape writer, key table, text arena) move into a shared `//tape` module first. JSON and YAML become two producers behind it. `yaml.seam` generates the SVM `@CFunction` and JVM FFM bindings, mirroring `json.seam`.

**Tech Stack:** C++17; rapidyaml 0.16.0 built with `RYML_WITH_TAB_TOKENS` and `ParserOptions::resolve_tags(true).resolve_tags_all(true)`; simdutf (`//bazel:unicode`) for UTF-8 validation, UTF-16/32 input transcoding, base64 and the UTF-16 text arena; Myna 0.9.1 values ABI v3 (`myna_value_node`, `ValueTape`, `SimdNativeValueTape`) and its seam generator; GraalVM `25.5.5-elide.24` SVM and JVM FFM; the Truffle DSL; Bazel with Linux amd64 RBE. Test-only: yaml-test-suite `data-2022-01-17`, `org.snakeyaml:snakeyaml-engine:3.2`. Benchmarks only: also `org.yaml:snakeyaml:2.7` and `com.fasterxml.jackson.dataformat:jackson-dataformat-yaml:2.22.4`.

**Spec:** The decisions below are the spec. They inherit `JSON_PLAN.md` (storage contract, ownership, verification), `docs/superpowers/plans/2026-11-06-json-completion.md` and its ledger (every SVM and compiled-code ruling stands), and `docs/superpowers/plans/2026-11-06-json-performance.md` (sessions, borrowed parse, sink v2 with `JsonText`, key-hash side table, position hints, presized tape writer, text arena, streams).

## Decisions (with evidence)

### D1. Parser: rapidyaml behind our own event handler

Every candidate was measured on one host, an Apple M5 Max (arm64, macOS, Homebrew clang 23.1.1 `-O3 -DNDEBUG`, Rust nightly 2026-10-07 release with thin LTO, GraalVM 25.5.5 JIT). Each figure is the best of 7 rounds. The C/C++ subset was re-run on BuildBuddy RBE Linux x86-64 through `bazel test` with the Elide toolchain. "Scan" consumes every event and touches every scalar. "Tape" also builds a Myna tape with core-schema scalar resolution through Myna's own builder (C++ `value_builder` or Rust `Builder`). For SnakeYAML and Jackson, "tape" means "load to Java objects".

- ASan+UBSan (`-O1`, recovery off) produced no reports over the 402 suite inputs and 11 fixtures for:
  - rapidyaml in both configurations;
  - libyaml;
  - libfyaml.
- rapidyaml compiles serially in 6.0 s (13 translation units plus one handler instantiation). It produces a 771 KB archive, and the instantiated parse engine is 148 KB of text.
- libyaml compiles in 0.9 s to a 128 KB archive.
- libfyaml builds 117 objects through CMake into an 862 KB archive. Its build includes a generated `config.h` and BLAKE3 assembly.
- The Rust probe binary with three parsers is 845 KB.

Findings that decided against the alternatives:

- **libfyaml** is fully conformant but 4.5× slower than rapidyaml on block records. Reusing a parser through `fy_parser_reset()` raised a spurious error on a valid 223 KB input (`records-flow-lines.yaml`), while a fresh parser accepted it (**measured**, `native-arm64.txt` note). Its build needs hand-maintained configuration.
- **saphyr / yaml-rust2** are memory-safe and 401/402, but 5.3–5.8× slower than rapidyaml on block records. They would also add a second Rust static library to SVM images, which CSV D1 flagged as a risk.
- **libyaml / unsafe-libyaml** fail 72 cases and implement YAML 1.1 behaviour.
- **SnakeYAML Engine** is the reference JVM implementation. It fails 45 cases (`conformance/failures-snakeyaml-engine-3.2.tsv`), and its load path runs at 17 MB/s on block records. It becomes the differential oracle (Task 8), with those 45 cases excluded by list.

The cost of the tape is the remaining lever. rapidyaml's own integer event handler scans block records at 403 MB/s. Going through Myna's `value_builder` drops that to 296 MB/s, a 27% builder tax that matches the JSON performance plan's diagnosis (§1.1). A direct handler writing through the presized `tape_writer` (JSON performance Task A2) is **estimated** at 330–400 MB/s on this host. The handler replaces the integer handler's own event writes, so the cost lies between the scan time (600 µs) and the scan plus ~4 ns for each of the 31,001 nodes (724 µs). Task 2's gate is set against the scan rate measured in the same run, not against an absolute value.

One probe artefact is worth recording. Without `-DNDEBUG`, rapidyaml's parse assertions rescan the rest of the line for every scalar, so single-line flow documents become quadratic: 0.8 MB/s on a 222 KB line. With `NDEBUG` the rate is flat at 459–474 MB/s from 5 KB to 222 KB (**measured**, `longline-arm64.txt`; the assertion build is in `longline-assertions-arm64.txt`). On RBE it is 231–239 MB/s from 11 KB to 222 KB (`rbe-x86-64-selected.txt`). rapidyaml must therefore always build with its assertions off (`RYML_USE_ASSERT=0`, `C4_USE_ASSERT=0`), including in sanitizer and test builds. The one exception is a dedicated assertion lane. Task 1 pins this with a scaling test.

### D2. Spec, scope and defaults

The default is strict YAML 1.2.2 with the core schema (§10.3). Each relaxation is an explicit option. The only compatibility bundle is `YamlOptions.yaml11()`.

| Topic | Default (`YamlOptions.DEFAULT`) | Options |
| --- | --- | --- |
| Version | YAML 1.2.2. A `%YAML 1.1` directive is accepted and recorded, but resolution does not change. `%YAML 2.x` is rejected. | `VersionDirective.HONOR`: `%YAML 1.1` documents use the 1.1 schema |
| Schema | Core: `null`/`Null`/`NULL`/`~`/empty, `true`/`false` in 3 casings, ints `[-+]?[0-9]+`/`0o..`/`0x..`, floats incl. `.inf`/`-.inf`/`.nan` | `JSON` (only JSON-spelled plain scalars resolve; any other plain scalar is an error), `FAILSAFE` (every scalar is a string), `YAML_1_1` (below) |
| 1.1 forms under core | `yes`/`no`/`on`/`off`/`y`/`n` are strings, `0755` is the int 755, `1:20` is a string, `2001-12-14` is a string, `<<` is an ordinary key | `YAML_1_1`: those booleans, octal `0755` = 493, binary `0b`, sexagesimal, `_` digit separators, `.inf` variants, implicit timestamps (string + `!!timestamp` tag), merge keys on |
| Streams | `decode`/`parse` accept zero or one document (zero yields root `null`). More than one is an error naming the stream API. | `documents(byte[])`, `stream(...)` for multi-document input |
| Duplicate keys | Rejected after resolution: `{1: a, 0x1: b}` is a duplicate, and so is `{1: a, "1": b}` because tape keys are strings (D3) | `DuplicateKeys.LAST_WINS` (the earlier entry is removed from the tape) |
| Anchors / aliases | Allowed as reference nodes, resolved on read, with expansion budgeted (D4) | `Aliases.REJECT` |
| Merge keys `<<` | Off: `<<` is an ordinary string key | `mergeKeys(true)`, or on under `YAML_1_1` |
| Core tags | `!!str`, `!!int`, `!!float`, `!!bool`, `!!null`, `!!seq`, `!!map` are enforced: a scalar must match the tag, and `!!str 12` is the string `"12"` | — |
| 1.1 type tags | `!!binary` → STRING (base64 text, validated), `!!timestamp` → STRING (grammar validated), `!!set` → OBJECT with null values, `!!omap`/`!!pairs` → ARRAY of single-entry OBJECTs. The tag is kept in the side table. | — |
| Unknown tags (`!foo`, `!<tag:x,2000:y>`, `%TAG` handles) | Preserved: the node takes its natural kind (a scalar is an unresolved STRING) and the resolved tag URI goes in the side table. The non-specific `!` forces a string. | `UnknownTags.REJECT` |
| Non-string scalar keys | Stored as STRING key nodes holding the scalar's text. The original kind (null, bool, int, float) is in the side table, so a sink can rebuild typed keys. | — |
| Complex keys (`? [a, b] : c`, `{a: 1}: x`) | Rejected: `IllegalArgumentException("YAML complex key")` | Deferred (see Deferred) |
| Comments | Skipped and not retained | — |
| Input encoding | UTF-8 (BOM skipped), and UTF-16LE/BE or UTF-32LE/BE with a BOM, transcoded natively. Strict UTF-8 validation and the YAML printable set (c-printable) are enforced over the whole input before parsing. | — |
| JSON-compatible subset | Every JSON text parses to the same tape as the JSON backend. Task 8 pins this differentially. | `YamlOptions.json()` = `JSON` schema + `Aliases.REJECT` + `UnknownTags.REJECT` |

### D3. Mapping onto the Myna tape (ABI v3) and the side tables

One tape per document, in the session arena, exactly as JSON:

| YAML | Node | Notes |
| --- | --- | --- |
| null forms | NULL | — |
| bool forms | BOOL | — |
| int in `int64` | I64 | `0o17`, `0x1F`, and in 1.1 `0b`, `0755` and `1_000` normalized |
| int above `int64` within `uint64` | U64 | — |
| larger ints | DECIMAL | The token is the canonical decimal digits, written to the arena for hex, octal and binary spellings. |
| float | F64 | Finite tokens use `std::from_chars` (nearest binary64). `.inf`, `-.inf` and `.nan` are written as non-finite F64 bits (below). Tokens that overflow (`1e400`) become DECIMAL, as in JSON. Their text is normalized to JSON grammar (`+` dropped, `.5` → `0.5`, `1.` → `1.0`), with the spelling kept in the lexical span. |
| string (any style) | STRING | Inline up to 16 bytes, otherwise a region reference into the retained input (filtered in place) or into rapidyaml's arena (scalars that grew during filtering). |
| sequence | ARRAY | — |
| mapping | OBJECT | Keys are STRING nodes (above) |
| alias `*a` | NULL with the ALIAS side bit | Resolved by readers to the anchored node (D4) |

Side tables are published next to the JSON performance plan's `lexical` spans and `key_hashes` (A1), all with one entry per node:

- `lexical` (`uint64`, shared with JSON): `offset << 32 | length` of the node's source token. It is valid for plain scalars always. For quoted, multi-line and block scalars it is valid only with `retainSource(true)`, which keeps a pristine copy because rapidyaml filters scalars in place. Otherwise those spans are 0.
- `key_hashes` (`uint32`, shared with JSON): FNV-1a of the decoded key bytes, plus the ASCII bit.
- `yaml_meta` (`uint32`, YAML only):
  - bits 0–2: style (0 plain, 1 single, 2 double, 3 literal, 4 folded, 5 block container, 6 flow container);
  - bit 3: anchored;
  - bit 4: alias;
  - bits 5–7: key kind (0 string, 1 null, 2 bool, 3 int, 4 float);
  - bits 8–31: the tag index (0 = none), or the alias ordinal when bit 4 is set.

Result-level tables:

- `tags`: interned resolved tag URIs, each `(offset, length)` into an arena region;
- `anchors`: `(node, name offset, name length)`;
- `alias_targets`: one node index per alias ordinal;
- `directives`: the `%YAML` version and `%TAG` pairs.

Number text on YAML owners:

- `numberText()` always returns JSON-grammar text: the token itself when it is already JSON-spelled, otherwise its normalized form (`0x1F` → `31`, `+1.5` → `1.5`, `.5` → `0.5`).
- `rawText()` returns the source spelling. For a number it does so whatever `retainSource` says, because numbers are single-line plain scalars that in-place filtering never rewrites.

What ABI v3 cannot represent, and how it is handled:

1. **Tags, anchors and styles** live in the side tables above. A Myna-only reader sees plain data.
2. **Aliases** become NULL nodes with a side-table target. Myna-only readers see `null` there. Upstream request M7 asks for a reference node kind in ABI v4.
3. **Non-finite floats.** Myna's builder and `ValueTape.validate()` reject non-finite F64. TruffleData never calls `validate()` on its own tapes (JSON precedent: no call in `json/src`), and its tape writer writes the IEEE bits. Upstream request M6 asks for a descriptor flag that makes this legal Myna. Until then a YAML tape is valid Myna except for those F64 bits, and `docs/YAML.md` says so.
4. **Complex keys** are rejected (D2).
5. **Comments** are dropped.

### D4. Anchors, aliases and resource limits

- An alias whose anchor is still open (`&a [*a]`) is an error ("recursive alias"). Cycles are therefore impossible, and every alias target is a complete earlier subtree. An alias to an undefined anchor is an error. Redefining an anchor rebinds it for later aliases, as the spec requires.
- The tape stores references, so decode memory is O(input) for any alias graph, and a billion-laughs document costs a few hundred nodes.
- Expansion happens only where a consumer materializes values, and it is charged against `YamlLimits.maxAliasExpansion` (default 1,000,000 nodes per export or typed decode):
  - export into a sink that returns `false` from `alias(id)`;
  - typed-plan decoding.

  Snapshots copy the tape with its references and never expand.
- Guest reads through interop resolve an alias in O(1): one side-word load, a branch, and an `alias_targets` load. That path never expands.
- `TapeSink.alias(int id)` returning `true` means the sink reused the object it built for `anchor(id)`, so the alias costs O(1). Anchor ids number anchor definitions densely per document, so a redefined name gets a new id.
  - A sink may return `true` only for an id whose `anchor(id)` it received during the current export. A subtree export whose alias points outside the subtree is therefore expanded.
  - `JavaSink` and `TruffleSink` reuse objects this way, which preserves object identity as `js-yaml` and `yaml` do.
- Merge keys are resolved at mapping end. Merged entries become key copies plus alias-reference values (no deep copy). Explicit keys override, earlier merge sources win, and merged entries sit at the position of `<<`. Merging a non-mapping is an error.
- `YamlLimits(maxInputBytes, maxIndexBytes, maxNodes, maxTextBytes, maxDepth, maxAliases, maxAliasExpansion)`, `DEFAULT = (64 MiB, 64 MiB, 1,000,000, 64 MiB, 128, 10,000, 1,000,000)`. Depth is checked in the handler on every `begin_*`. rapidyaml's own allocations go through `c4::yml::Callbacks` into the session's counted resource, so they are charged to `maxIndexBytes`.

Typed plans resolve scalars by the schema, not by the core schema (serde-yaml behaviour):

- A plain `1.0` read into a STRING field is `"1.0"`.
- `0x1F` read into INT64 is 31.
- A quoted scalar fits only STRING.
- `.inf` and `.nan` fit FLOAT64.
- Aliases expand within budget, and merge keys apply when enabled.
- Unknown and duplicate fields are rejected as in JSON.

| Failure | Exception |

## Global Constraints

- Everything in the JSON completion and performance plans' Global Constraints applies to `//yaml` and `//tape`. In particular:
  - native calls use normal transitions except the documented bounded `session_reset` leaf;
  - nothing ever silently falls back to another parser;
  - owners are thread-confined, and closing one invalidates compiled cached reads;
  - Java compiles under NullAway/JSpecify (`@NullMarked`) and the Truffle DSL through `data_java_library`;
  - performance claims come only from the harness, with raw samples retained under `benchmarks/results/yaml-*`.
- rapidyaml is pinned to 0.16.0 (`rapidyaml.v0.16.0.src.tgz`, SHA-256 `a0ce80a8f4211580c8703e57acb813a28ca6ec80908f6eb926be94be8e98d39d`).
  - It always builds with `RYML_USE_ASSERT=0`/`C4_USE_ASSERT=0` (assertions off, whatever `NDEBUG` says), `RYML_WITH_TAB_TOKENS` and `RYML_DEFAULT_CALLBACK_USES_EXCEPTIONS`. All four are propagated through `defines`.
  - The handler always runs with `resolve_tags(true).resolve_tags_all(true)`.
  - The dedicated assertion lane (`@rapidyaml//:ryml_assert`, Task 1) is the only build with assertions on.
  - No patch is applied. Any later patch needs a ledger ruling and an upstream link.
- rapidyaml exceptions never cross the C ABI: every `td_yaml_*` entry point catches and maps them to a status. Error messages are copied into the result (bounded at 256 bytes), with line and column.
- The input is validated as strict UTF-8 and c-printable (simdutf plus a control-byte scan) before rapidyaml sees it. rapidyaml does not validate encoding.
- Strict defaults are as in D2. Every relaxation is a `YamlOptions` field, and no environment variable or system property changes semantics.
- Every native allocation path, including rapidyaml's callbacks, has a failure-injection test and passes ASan/UBSan:

  ```sh
  bazel test //yaml/native:all //tape/native:all \
    --copt=-fsanitize=address,undefined --copt=-fno-sanitize-recover=all --linkopt=-fsanitize=address,undefined
  ```

- Compiled gates, as in JSON:
  - observed compiled execution;
  - `TreatPerformanceWarningsAsErrors=all`;
  - Graal graphs of at most 10,000 nodes and ASTs of at most 192 nodes;
  - at most **0.05 Java bytes per read** for typed, generic, interop and alias-resolving reads;
  - an export walk with a non-allocating sink allocates at most 1.0 B per document.
- SVM targets are `manual`, Linux x86_64, through RBE: `bazel test //yaml/tests:native_test`. JVM tests: `bazel test //yaml/tests:jvm`.
- Commit messages use the repository prefixes and end with a blank line, then `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A billion-laughs document must decode in O(input) memory and fail at `maxAliasExpansion` when materialized.** It must not fail at decode, and it must not exhaust memory. Interop reads through aliases must not expand. Pinned by Task 3's `alias_graph_is_linear` (native, 10 levels × 10 aliases → fewer than 200 nodes) and Task 5's `YamlExportTest.billionLaughsFailsAtExpansionLimit`.
2. **A recursive alias (`&a [*a]`, `&a {k: *a}`) and an alias to an undefined anchor are errors, never cycles.** Pinned by Task 3's `recursive_alias_rejected` and `undefined_alias_rejected`.
3. **1.1 and 1.2 resolution must not leak into each other.**
   - Under CORE: `on`, `yes` and `y` are strings, `0755` is 755, `1:20` and `2001-12-14` are strings, and `<<` is a key.
   - Under YAML_1_1: they are true, 493, 80, a timestamp and a merge.
   - `!!str 0x1F` is the string under both.

   Pinned by Task 3's `schema_boundaries`.
4. **Duplicate keys are detected after resolution and after stringification.** Cases:
   - `{1: a, 0x1: b}`, `{1: a, "1": b}` and `{null: a, ~: b}` are rejected;
   - `{a: 1, "a": 2}` is rejected;
   - under `LAST_WINS`, `{a: 1, a: 2}` reads 2 with size 1.

   Pinned by Task 3's `duplicate_keys_after_resolution`.
5. **Every yaml-test-suite case passes through our own handler.** Each suite input decodes to a tape whose rendered event stream equals `test.event`, or fails when `error` exists, with an empty expected-failures list. Pinned by Task 3's `//yaml/conformance:yaml_test_suite`.
6. **A borrowed YAML parse must never let a view observe the next decode.** Pinned by Task 5's `borrow_invalidated_by_next_parse`, the JSON performance plan's Focus 1 test run on YAML in interpreted and compiled code.
7. **Stream splitting must equal the whole parse at every chunk boundary.** This includes a `---` inside a block scalar that is indented (content) or at column 0 (a document end, c-forbidden). Pinned by Task 3's `stream_split_matches_whole_parse`.
8. **The JSON subset must agree exactly with the JSON backend.** Every JSON fixture and generated document decodes through YAML to a tape whose nodes, text and number kinds equal the JSON tape. That includes `-0` → F64 −0.0, `1E400` → DECIMAL, `18446744073709551615` → U64 and escaped duplicate keys rejected. Pinned by Task 8's `JsonSubsetDifferentialTest`.

## Deferred (with triggers)

- **Complex keys:**
  - trigger: an Elide user files a document that needs them;
  - shape: `ComplexKeys.STRINGIFY` (canonical flow text as the key, kind COMPLEX in the side table) or `PAIRS` (the mapping as an ARRAY of `[key, value]`).
- **A direct typed handler** (rapidyaml → slots without a tape): trigger is when Task 6 measures the tape → slots walk above 15% of typed decode.
- **A JSON fast path** (JSON-shaped YAML routed to simdjson):
  - trigger: Elide telemetry shows JSON-shaped YAML is common and `yaml-flow` trails JSON by more than 1.5×;
  - this is a selection, not a fallback: invalid JSON still goes to rapidyaml, which gives the YAML answer.
- **Big-document frames** (the JSON performance plan's G1/G2) for YAML: trigger is a YAML input above 16 MiB in a real workload.
- **A YAML emitter** (`YAML.stringify`): needs its own plan. rapidyaml's emitter or a tape writer are the candidates.
- **Round-trip editing with comments:** non-goal.
- **libfyaml as a second native oracle:** trigger is a SnakeYAML Engine exclusion list growing past 60 cases.

## Open questions for the user

1. **Shared names.** Rename the unreleased JSON types to `Tape*` in `//tape` (proposed), or keep `JsonValue`/`JsonSink` and have YAML return JSON-named types?
2. **`YAML.parse` defaults in Elide.** The proposed default is YAML 1.2 core, unique keys, merge keys off, and aliases with identity, which matches the `yaml` npm package's defaults. The other option is js-yaml-style defaults: merge keys on and duplicate keys last-wins.
3. **Non-finite floats** before Myna M6. Write non-finite F64 bits on YAML tapes (proposed), or store `.inf`/`.nan` as DECIMAL-like tokens and keep strict Myna validity?
4. **`%YAML 1.1` documents.** Keep the core schema and record the directive (proposed default), or honour the directive by default?
5. **New artifact.** Publish `truffledata-tape` as its own BOM-managed artifact (proposed), or package the shared classes inside each format artifact?
6. **Upstream requests.** File Myna M6/M7 now, and the two rapidyaml documentation issues?
