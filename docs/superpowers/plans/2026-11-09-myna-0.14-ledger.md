## F1 — ABI class split (aarch64 Linux bindings)

### Problem

Myna 0.14.0 (elide-dev/myna#71) makes C `char` signedness part of the target ABI class.
`x86_64-unknown-linux-gnu` and `aarch64-apple-darwin` keep one class; `aarch64-unknown-linux-gnu`
(AAPCS64, unsigned `char`) is its own class with its own fingerprint, even for seams without a
`char` carrier. Every seam's genrule ran `validate --targets <all three>` and required one shared
fingerprint, so every bindings target failed (`targets have different ABI fingerprints`).

### Measured: what differs between the classes

Generated every seam (json, yaml, csv, buffa) for all three targets with the 0.14.0 generator and
diffed. Between the two classes the outputs differ only in the 64-hex fingerprint constant
(`<Class>.java`, `<Class>FFM.java`, `seam.rs`, `seam.h`, `seam.abi`, `seam.ll` metadata) and the
descriptor's `"charUnsigned":true`; `seam.ll`'s `target triple` already varied per target. Nothing
else: no layout, carrier, policy or metadata change. `seam.abi` is the SHA-256 of `seam.json`.

| seam | `LP64_LITTLE` (x86-64 Linux, Apple arm64) | `LP64_LITTLE_AAPCS64` (aarch64 Linux) |
| --- | --- | --- |
| json | `e81b2700…349894e` | `75650642…fa2fcf301` |
| yaml | `f9db8ac8…d30ccdaf` | `4f45fabe…46d72d5ce` |
| buffa | `e35513fb…aaacc8de` | `7ee600fb…ba7342767` |
| csv | `e13e8c09…91dbf30b` | `784f2bd0…ec5dc22a` |

### Design choice: (a) one bindings jar per format

Since the generated code differs only in a constant, each bindings jar is published once and
carries both classes' fingerprints with a selector; option (b), per-class classifier jars, would
duplicate identical code and complicate every consumer POM for one string.

- `bazel/myna.bzl` `myna_bindings`: validates each class across its release targets
  (`x86_64-unknown-linux-gnu,aarch64-apple-darwin` must share one fingerprint;
  `aarch64-unknown-linux-gnu` alone), generates for the configured target (so a static image's
  `<Class>.java` is already its own class's), then generates each class's representative target
  and runs `bazel/myna_abi.py`, which:
  - fails the build if the two classes' outputs differ in anything but the fingerprint (and the
    descriptor's `charUnsigned`), the guard that would send us to option (b);
  - emits `<Class>Abi.java` (`JsonAbi`, `YamlAbi`, `BuffaAbi`, `CsvNativeAbi`) with
    `LP64_LITTLE`, `LP64_LITTLE_AAPCS64` and `fingerprint(boolean charUnsigned)`;
  - rewrites `seam.h` so `TRUFFLEDATA_<X>_SEAM_ABI` is selected by `#ifdef __CHAR_UNSIGNED__`:
    the compiler's own statement of Myna's class criterion, so the C providers (`api.cc` returns
    the macro), the published `-native.h` headers, the isolated archive tests and the Cargo crates
    get the right class's fingerprint on any target, musl included;
  - keeps `generated/abi/<class>/seam.{abi,json}` for the contract check and tests.
- The cells seams (`protobuf-buffa/cells`) use the macro with `abi = False` and now generate for
  the configured target, so the derived descriptors equal the production descriptor of the same
  class on arm64 too.
- `core` gains `TargetAbi` (`LP64_LITTLE`, `LP64_LITTLE_AAPCS64`; `HOST` decided once from
  `os.name`/`os.arch`: Linux + aarch64/arm64 is AAPCS64, every other supported host the signed
  class).
- JVM/FFM consumers (`JsonJvm`, `YamlJvm`, `FfmBackend`, `CellsFfmBackend`, `FfmIndexer`) compare
  the library's fingerprint with `<Class>Abi.fingerprint(TargetAbi.HOST.charUnsigned())`; the
  mismatch message names the expected class. SVM consumers (`JsonSvm`, `YamlSvm`, `SvmBackend`,
  `SvmIndexer`) use `<Class>Abi.fingerprint(Platform.includedIn(Platform.LINUX_AARCH64.class))`,
  which Native Image folds at image build time, so an image holds exactly one class's constant
  and no decode path changed (the check stays behind the existing one-time `verified` guard).
  A mismatch still throws `IllegalStateException`; nothing falls back.
- Release gates: `check_natives.py` takes both fingerprints from the bindings jar's generated
  `<Class>Abi` (sources jar constants, which must be exactly the compiled class's 64-hex
  strings) and requires each platform's library to hold its class's fingerprint
  (`linux-aarch64[-musl]` → AAPCS64, the rest → signed) and not the other class's.
  `bazel/myna_contract.py` accepts either class's `targetAbi`, verifies per class that
  `seam.abi` = SHA-256(`seam.json`), that the classes' descriptors differ only in `charUnsigned`,
  that the configured descriptor is one of them, and that the jar's `<Class>Abi` constants are
  exactly those fingerprints; it now covers the CSV seam too. `test_release.py` asserts each
  bindings jar ships its `<Class>Abi`. `maven_repo.py`/`publish.sh` are unchanged: still one
  bindings jar per format.
- Cargo crates (`json/native/crate`, `csv/native/crate`): `vendor.sh` refreshed (the
  class-selected `seam.h`; Myna's `values.hpp` moved to 0.14.0's text append/hash); `build.rs`
  reads the `#ifdef`/`#else` defines and picks AAPCS64 for `CARGO_CFG_TARGET_OS=linux` +
  `CARGO_CFG_TARGET_ARCH=aarch64`, mirroring the compiler's branch; `tests/link.rs` checks the
  linked fingerprint equals that class's define.

### Tests added

- `//tests:test` `TargetAbiTest`: the host mapping (Linux aarch64/arm64 → AAPCS64; Linux amd64,
  macOS → signed; `HOST` decided once).
- Per format (`//json/tests:jvm` `FfmAcceptanceTest`, `//yaml/tests:jvm` `YamlIntegrationTest`,
  `//protobuf-buffa/tests:{jvm,jvm_non_strict}` and `//protobuf-buffa/cells/tests:jvm`
  `AcceptanceTest`, new `//csv/tests:jvm_native_abi` `CsvNativeAbiTest`):
  `<Class>Abi.LP64_LITTLE[_AAPCS64]` equal the per-class `seam.abi` files and differ; the
  AAPCS64 constant is what `TargetAbi.of("Linux","aarch64")` selects; and a library reporting
  the *other* class's fingerprint (`other_abi_class.so`, generated from the per-class `seam.abi`
  and selected with `__CHAR_UNSIGNED__`, so on every host it is the wrong one) is rejected with
  `IllegalStateException` "ABI fingerprint mismatch" while this host's library is accepted. On
  `--config=remote_arm64` the rejected fingerprint is the signed class's and the accepted one
  AAPCS64's; on amd64/macOS the reverse.
- `json/tests/SvmAcceptance`: the linked archive's fingerprint equals the image's class constant
  and not the other class's.
- `tools/release/test_check_natives.py` `AbiClassTest`: the per-class extraction and its
  inconsistency rejections.
