Task 1: Ruling: diagnostics number records from 1 counting every physical record including the header (empty lines are not records); `CsvRow.record()` stays the 0-based data-record index — a 1-based physical number is what a person counts in the file and cannot be confused with the row index — cost if wrong: a base change in CsvScanner.syntax and BatchBuilder.
Task 1: Ruling: maxRecordBytes caps every record's content (terminator excluded) on every path, checked by the scanner when a record completes — the span length field is 30 bits, so whole-input parses also need the cap — cost if wrong: one comparison per record.
Task 1: Ruling: a lone CR at a non-final buffer's end is consumed when it starts an empty line — whether an LF follows or not it ends an empty line, so the parse is identical — cost if wrong: none (records ending in CR are still reported incomplete).
Task 1: Ruling: trim also forbids a blank quote byte when quoting is on, besides the planned blank-delimiter rule — a blank quote would be swallowed by trimming — cost if wrong: one relaxed check.
Task 1: Ruling: the scanner exposes recordBase/byteBase fields that callers set for diagnostics, and the span helpers (offset/length/quoted/escaped/unescape) are static on CsvScanner — keeps the file list and makes rebasing a field write — cost if wrong: none.
