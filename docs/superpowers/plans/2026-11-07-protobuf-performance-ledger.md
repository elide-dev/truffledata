## Task A1 — layout compiler and slab format

Task A1: Ruling: record order is presence words · `handle` · `unknown` · oneof case entries · 8-byte slots · 4-byte slots (Step 3), not §2.1's "cases before handle"; the case area is padded to 8 so 8-byte slots stay aligned — cost if wrong: none for readers (offsets come from `Layout`); a 1–2-oneof record spends 4 bytes more than a 4-byte-padded case area would, which could not have kept 8-byte slots aligned anyway.
Task A1: Ruling: oneof case entries are `u16` holding the member's **ordinal + 1** (0 = none), not `u8` — an `u8` cannot name members past 255 and §2.1 says every `ProtoPlan` schema is eligible; `Layout` rejects only a oneof member whose ordinal exceeds 65,534 — cost if wrong: one byte more per oneof (absorbed by the 8-byte padding for up to four oneofs).
Task A1: Ruling: header words 20 and 24 are `root` (always 32) and `layout` (the `TDL1` fingerprint) instead of §2.1's `byteRegion`/`unknownRegion`: every allocation (records, string headers with inline payload, lists, per-record unknown spans) comes from one bump cursor in decode order, so a single-pass producer needs no region sizes up front, and the fingerprint lets an owner reject a slab of another layout in one compare — cost if wrong: a later format that wants payload-free record regions (e.g. for borrowing) needs a format version bump and a second cursor in both producers.
Task A1: Ruling: placement is fully specified for byte-identical producers (docs/SLAB.md "Decoding into a slab"): strings/bytes allocate their header when read, child records when entered, and at record close, in order, merged singular children, the empty value of a map entry without one, lists in ordinal order, then the unknown span; orphans (cleared oneof members, overwritten singular values, a merged message's first record, map entries moved to unknown fields) keep their bytes and handles — cost if wrong: packed runs cannot be decoded in place into their final list (Task A2/A3 decode them into pending scratch and copy at close, one memcpy per packed field), and orphans waste slab bytes on inputs with duplicates.
Task A1: Ruling: a singular message seen again is a merge: the first occurrence is decoded in place, every later payload is validated by a decode walk that writes nothing (so a payload later cleared by a oneof still fails exactly where `ProtoCodec` fails — the reference model's first draft deferred validation and the differential test caught it), and at close the concatenation of all payloads since the last clear is decoded into a fresh record (`CERTIFIED` cleared) — cost if wrong: merged messages are decoded twice and orphan their first record; merges are rare and already uncertified in ABI 9.
Task A1: Ruling: for implicit-presence fields the presence bit is `ProtoRow`'s non-default rule (`-0.0` present, `""` absent), not "present on the wire" as §2.1 words it, so `has()` and the bit agree on explicit zeros; the slot keeps the last value (string slots keep the header offset), and presence bits are authoritative — cost if wrong: none semantically; one header allocated per explicit empty implicit string.
Task A1: Ruling: map lists are deduplicated by the producer (key's first position, last entry), and an entry without its message value gets an empty value record, exactly as `ProtoCodec` builds maps; the slab therefore holds map semantics, not raw entries — cost if wrong: producers pay a key comparison per map entry at close (B1's lazy directory still serves lookups).
Task A1: Ruling: unknown bytes are always copied into the slab, also in borrowing slabs (§2.1's "input spans when borrowing" dropped) — cost if wrong: a borrowing slab with large unknown payloads copies them; a span form can be added behind a flag bit in Phase D.
Task A1: Ruling: per-string `EXTERNAL` bit (length bit 30) marks an input-offset payload so owning slabs can still borrow `bytes` ≥ `borrowBytes` (user decision Q1); `OWNING`/`BORROWING` say whether any header is external; payload lengths are limited to 2^30 − 1 — cost if wrong: strings over 1 GiB are rejected (already far above `maxStringBytes`).
Task A1: Ruling: producers never reject missing required fields; they clear `CERTIFIED` (also on merges) and the owner checks required presence before exposing an uncertified slab (§2.1 eligibility, A2's `CERTIFIED`) — cost if wrong: the B1 owner must walk uncertified slabs; inputs with merges pay that walk.
Task A1: Ruling: bool list elements are one byte (0/1), bool slots a `u32` — cost if wrong: none for 4-byte-aligned readers; lists pad to 8 at the next allocation.
Task A1: Ruling: the `TDL1` field entry is three words — slot, kind code (`SlotKind.ordinal() + 1`), oneof index (0xFFFFFFFF none) — not two, because TDB3 carries no oneof membership and the Rust producer needs it; child type indices come from TDB3. ## Task A2 — native slab decoder and seam ABI 10

Task A2: Ruling: format change to meet the slab-size gate (A1 flagged Type message 1 at 536 B, 4.39 ×): a record starts with its `handle` word, then **`u32` presence words** (`W = ceil(n / 32)`), then the `u16` case entries, with slots aligned to 8 only when the type has an 8-byte slot; the per-record `unknown` word is gone, replaced by an **unknown table** (header word 28, formerly reserved: `count · 0 · (record, span)*` ascending by record, the last allocation); **ASCII string headers are 8 bytes** (`length · handle`, no `utf16` word; non-ASCII strings and bytes keep 12). Message 1 is now 448 B (3.67 ×; all 32 small messages 3.65 ×, holdout 3.21 ×, large 3.33 ×). Dropping only the unknown word or only the handle would not have passed: with 8-byte record alignment the 10-slot `Field` record stays 56 B unless both header words shrink. `docs/SLAB.md`, `Layout`, `SlabFormat`, `SlabReference`, the ten goldens, `LayoutTest`'s hand-written words (re-derived and re-checked by hand) and `TypedAcceptance.schemaProgramGolden`'s TDL1 tail changed together; `TDL1` keeps version 1 (nothing has shipped it) — cost if wrong: readers pay a binary search for `encode()`'s unknown spans (rare), records with more than 32 fields need one more presence word per 32 fields instead of per 64, and string readers branch on the ASCII bit for the payload offset (they already did for the UTF-16 length).
Task A2: Ruling: `NEEDS_CAPACITY` is exact by continuing the same walk: allocations that do not fit `capacity` are not written, records that do not fit are kept in decoder frames (their presence and slots are read later: merges, map defaults, required checks), map keys are captured from the entry's frame and the input at entry close (never read back from the slab); so `SIZING_ONLY` is the same pass with capacity 0 and errors are identical with or without room. A slab longer than `maxSlabBytes` is `BUDGET` as soon as the cursor passes it (never `NEEDS_CAPACITY`) — cost if wrong: frames cost `(maxDepth + 2) × max recordBytes` of scratch when a large record overflows.
Task A2: Ruling: merges decode the remembered payloads **one after another into one record** instead of concatenating them into a merge buffer (each payload was validated by its own walk, so no field spans two payloads; this is the concatenation's decode), and the walk is the decoder itself with writes disabled (writable limit 0, every record framed) and cursor, counts, `CERTIFIED` and unknown-table entries restored afterwards — cost if wrong: none semantically (`merge_matches_java_concatenation` compares with decoding the concatenation directly); A3's Java producer may implement either.
Task A2: Ruling: scratch (pending list elements, merge payload spans, unknown bytes, unknown-table entries, frames: about 20 KiB) is fixed stack storage in both entry points; `decodeSlab` spills to the heap when it overflows, `decodeSlabSmall` returns `BUDGET` (Java retries through `decodeSlab`, plan Interfaces). There is no thread-local or decoder-owned scratch, so `decodeSlab` allocates (and frees) per call for messages beyond the stack capacity (for example the 52 KB fixture's 2,048-entry list), deviating from §2.2's "no heap allocation in the steady state"; messages within it allocate nothing on either path (`small_entry_allocates_nothing` checks both) — cost if wrong: one allocation per large decode; a session scratch can be added in Phase D without an ABI change.
Task A2: Ruling: `SlabResult` is `bytes u64 · records u32 · handles u32 · flags u32 · error u32 · reserved u64`; on a rejection `error` is the input offset of the innermost field being decoded, and for invalid UTF-8 that of the string's first payload byte. Strings are validated when read, in wire order (including inside merge walks), so the first invalid string fails exactly where protobuf-java fails; `invalid_utf8_rejected_same_byte_as_java` pins the offset over 300 malformed strings in root, nested, repeated and merged positions. Only the UTF-8 offset is contractual for A3; other offsets are diagnostics — cost if wrong: A3 must reproduce one more number (the payload offset).
Task A2: Ruling: `maxDepth` has `ProtoCodec`/`SlabReference` meaning (root at depth 0; a record at depth `d` may contain messages, groups, unknown groups and a map entry's default value record only while `d < maxDepth`), which is ABI 9's `max_depth` minus one; values above 128 (ABI 9's bound) and `maxSlabBytes` above `Integer.MAX_VALUE` are `BUDGET` up front — cost if wrong: B1 passes `plan.maxDepth()` unchanged (not ABI 9's `+ 1`).

## Task A2b — restructure of the native slab decoder (SOTA plan §6)

Task A2b: Ruling: the decoder is one loop over an explicit record stack (`Decoder::run`; the frame index is the depth, `maxDepth` checked at push) instead of recursion: the top record's read position and body end (pointers), base, type and presence word 0 live in locals; a frame is written when a record opens and read when it closes. One-byte tags dispatch through a per-type 128-entry table (tag byte → ordinal + 1, wire type included, so a hit needs no further tag checks) to a 16-byte `Entry` (tag, slot, child, handler, flags, presence word); longer tags use the number lookup. Hot handlers (int/enum, 64-bit, zigzag, bool, fixed, string, bytes, singular and repeated length-delimited messages) are inline; repeated scalars and strings, oneof members, closed enums, map keys, groups, packed runs, unknown fields, merges and the record close with lists go through out-of-line paths returning one word (`slow`, `mismatch`, `merge_walk`, `string`, `finish`/`close`). Wire-order prediction (A2) is dropped: the table covers fields 1–15 without a compare, and the plan's `next`-index entry would cap slots, children and ordinals at 16/8/8 bits, which a universal decoder cannot impose — cost if wrong: fields numbered 16 and above pay one lookup-table load per occurrence (one load more than a predicted hit).
