## Task A1 — layout compiler and slab format

Task A1: Ruling: record order is presence words · `handle` · `unknown` · oneof case entries · 8-byte slots · 4-byte slots (Step 3), not §2.1's "cases before handle"; the case area is padded to 8 so 8-byte slots stay aligned — cost if wrong: none for readers (offsets come from `Layout`); a 1–2-oneof record spends 4 bytes more than a 4-byte-padded case area would, which could not have kept 8-byte slots aligned anyway.
Task A1: Ruling: oneof case entries are `u16` holding the member's **ordinal + 1** (0 = none), not `u8` — an `u8` cannot name members past 255 and §2.1 says every `ProtoPlan` schema is eligible; `Layout` rejects only a oneof member whose ordinal exceeds 65,534 — cost if wrong: one byte more per oneof (absorbed by the 8-byte padding for up to four oneofs).
Task A1: Ruling: header words 20 and 24 are `root` (always 32) and `layout` (the `TDL1` fingerprint) instead of §2.1's `byteRegion`/`unknownRegion`: every allocation (records, string headers with inline payload, lists, per-record unknown spans) comes from one bump cursor in decode order, so a single-pass producer needs no region sizes up front, and the fingerprint lets an owner reject a slab of another layout in one compare — cost if wrong: a later format that wants payload-free record regions (e.g. for borrowing) needs a format version bump and a second cursor in both producers.
Task A1: Ruling: placement is fully specified for byte-identical producers (docs/SLAB.md "Decoding into a slab"): strings/bytes allocate their header when read, child records when entered, and at record close, in order, merged singular children, the empty value of a map entry without one, lists in ordinal order, then the unknown span; orphans (cleared oneof members, overwritten singular values, a merged message's first record, map entries moved to unknown fields) keep their bytes and handles — cost if wrong: packed runs cannot be decoded in place into their final list (Task A2/A3 decode them into pending scratch and copy at close, one memcpy per packed field), and orphans waste slab bytes on inputs with duplicates.
Task A1: Ruling: a singular message seen again is a merge: the first occurrence is decoded in place, every later payload is validated by a decode walk that writes nothing (so a payload later cleared by a oneof still fails exactly where `ProtoCodec` fails — the reference model's first draft deferred validation and the differential test caught it), and at close the concatenation of all payloads since the last clear is decoded into a fresh record (`CERTIFIED` cleared) — cost if wrong: merged messages are decoded twice and orphan their first record; merges are rare and already uncertified in ABI 9.
Task A1: Ruling: for implicit-presence fields the presence bit is `ProtoRow`'s non-default rule (`-0.0` present, `""` absent), not "present on the wire" as §2.1 words it, so `has()` and the bit agree on explicit zeros; the slot keeps the last value (string slots keep the header offset), and presence bits are authoritative — cost if wrong: none semantically; one header allocated per explicit empty implicit string.
Task A1: Ruling: map lists are deduplicated by the producer (key's first position, last entry), and an entry without its message value gets an empty value record, exactly as `ProtoCodec` builds maps; the slab therefore holds map semantics, not raw entries — cost if wrong: producers pay a key comparison per map entry at close (B1's lazy directory still serves lookups).
Task A1: Ruling: unknown bytes are always copied into the slab, also in borrowing slabs (§2.1's "input spans when borrowing" dropped) — cost if wrong: a borrowing slab with large unknown payloads copies them; a span form can be added behind a flag bit in Phase D.
Task A1: Ruling: per-string `EXTERNAL` bit (length bit 30) marks an input-offset payload so owning slabs can still borrow `bytes` ≥ `borrowBytes` (user decision Q1); `OWNING`/`BORROWING` say whether any header is external; payload lengths are limited to 2^30 − 1 — cost if wrong: strings over 1 GiB are rejected (already far above `maxStringBytes`).
Task A1: Ruling: producers never reject missing required fields; they clear `CERTIFIED` (also on merges) and the owner checks required presence before exposing an uncertified slab (§2.1 eligibility, A2's `CERTIFIED`) — cost if wrong: the B1 owner must walk uncertified slabs; inputs with merges pay that walk.
Task A1: Ruling: bool list elements are one byte (0/1), bool slots a `u32` — cost if wrong: none for 4-byte-aligned readers; lists pad to 8 at the next allocation.
Task A1: Ruling: the `TDL1` field entry is three words — slot, kind code (`SlotKind.ordinal() + 1`), oneof index (0xFFFFFFFF none) — not two, because TDB3 carries no oneof membership and the Rust producer needs it; child type indices come from TDB3. The section follows the last TDB3 byte at the next multiple of 4 and is located by an 8-byte trailer `[section offset]['TDL1']`; its fingerprint is CRC-32 of the type tables. `NativeSchema` compiles the layout before staging (a layout contract failure is not reported as a budget failure) and the section counts against `maxSchemaBytes` — cost if wrong: Task A2 reads one more word per field; the existing budget tests (smallest passing budgets) still pass.
Task A1: Ruling: the appended section is invisible to ABI 9 — `typed_view::compile` and `typed.rs` reach data only through header offsets; `appended_layout_section_is_invisible_to_abi9` compiles programs with and without a section (descriptors, lookup tables, certification, enum sets identical) and runs 2 × 1,000 corpus inputs through the interpreted and view decoders with identical entries, directories and statuses — cost if wrong: the ABI 9 library would misread programs until Task A2 replaces it.
Task A1: Ruling: `ProtoPlan.layout()` is a lazily compiled, double-checked `volatile` field behind one `@TruffleBoundary` (budget 11 → 12; `Layout.java` budget 3: two `compile`s and `parse`), identity-stable per plan; each plan roots its own closure, and a schema program with an Any registry uses `Layout.compile(types)` in program order, so a slab is read with the layout whose fingerprint it carries — cost if wrong: two plans for one type (root vs nested) hold equal but distinct layouts; accessors key on identity (Review Focus 5), so they miss, never misread.
Task A1: Ruling: golden slabs are produced and checked by `SlabReference`, a deliberately plain executable model of docs/SLAB.md in the test tree, which `reference_model_matches_proto_codec` holds to `ProtoCodec` over 7 schemas × 1,500 generated inputs (accept/reject and every value, presence bit, oneof case and unknown span); the timestamp, map, oneof, unknown and merge slabs are additionally hand-written word by word; `type`, `lists`, `strings`, `wide` and `legacy` are model output checked field by field against `ProtoRow` and inspected by hand for `lists` and `legacy` — deviation: Type message 1 (536 B) is not hand-written word by word — cost if wrong: a model bug shared by the hand-checked reading would propagate to A2/A3; the differential corpus bounds it.
Task A1: Ruling (measurement, not a gate): Type message 1 of the consumer fixture is 536 B as an owning slab, 4.39 × its 122-byte input, against §1.2's 400–460 B estimate and Task A2's ≤ 4 × hypothesis: four 10-field `Field` records (56 B each, half the slots unused), 16 B of presence/handle/unknown per record (6 records) and 12-byte string headers dominate — cost if wrong: A2's slab-size gate fails on this schema; options are a side table for the rarely used per-record `unknown` word, or no per-record handle (handles derivable from allocation order), each saving 4 B per record.
Task A1: Deviation: the implementation was written together with the tests rather than after a recorded red run of `//protobuf-runtime/...` (the target did not exist before this task); red/green was observed on the reference model (two parser bugs and the merge-validation hole above).
